LunarSerpent

A scientific decision-support system for lunar surface analysis and rover traverse planning.

LunarSerpent presents a 3-D interactive Moon globe as its interface — but the globe is the front door to an analysis engine, not a visualisation in itself. The system ingests authoritative lunar datasets, derives terrain products, detects and classifies surface features, and plans safe rover traverses between user-specified selenographic coordinates.

The governing principle is scientific provability. Every displayed number traces to a documented formula with a peer-reviewed source. Where a quantity cannot be determined with justified confidence, the system states its uncertainty or declines to report it — rather than producing a plausible-looking value.

Run it

python run.py

That is the whole thing. It checks the environment, reports which datasets resolved and from where, starts the API, and opens the interface at http://127.0.0.1:8765/. On Windows run works too.

First time only:

python -m pip install -r requirements.txt
Command What it does
python run.py Preflight, then serve and open a browser
python run.py --check Preflight only — verify the environment and datasets, start nothing
python run.py --test Run the full test suite first; refuse to serve if it fails
python run.py --docs Rebuild docs/html/ before serving
python run.py --port 9000 Serve on another port
python run.py --no-browser Do not open a browser

The preflight is worth reading rather than skipping: it prints which of the candidate data roots each dataset resolved from, so a missing DEM is reported as a missing DEM instead of surfacing later as an error inside a memmap.

Ctrl+C stops it.

Scientific approach in brief

Concern Approach
Coordinates IAU Mean-Earth/Polar-Axis (DE421) frame, spherical datum R = 1737.4 km. All positioning by selenographic latitude/longitude; pixel indices exist only as the output of a verified transform
Topography LOLA LDEM_16 (1895 m/px), read directly from PDS3 via numpy.memmap. Higher resolutions streamed by HTTP range request at zero storage cost
Slope Horn (1981) 3×3 operator with latitude-corrected cell size — without which polar slopes are underestimated by up to 5.8×
Craters Robbins (2019) catalogue (1 296 879 craters, complete ≥ 1 km) as ground truth; DEM-based curvature + Hough detection below that limit
Boulders Shadow-length photoclinometry, h = L·tan(e), on metre-scale imagery within a selected area of interest
Classification Pike (1974, 1977) morphometric scaling; class boundaries follow physical transitions, not round numbers
Path planning A* with a proved admissible and consistent heuristic, plus cost-validated smoothing; benchmarked against 7 other algorithms

Deliberate scientific limitations

These are disclosed rather than hidden, and surface in the UI where relevant:

  • Global metre-scale boulder mapping is not attempted. It would require ~10¹⁴ pixels (hundreds of TB) and has never been done by any mission. Handled instead by a global catalogue plus on-demand high-resolution detail for a selected region.
  • Slope is scale-dependent. Every slope and roughness value carries its measurement baseline. A 1.9 km-baseline slope is not what a rover wheel experiences.
  • Crater age is inferred, never measured. Reported as three separate quantities: measured degradation index, stratigraphic epoch, and model age with explicit uncertainty.
  • Cylindrical projections fail at the poles. Above 85° latitude the system refuses cylindrical analysis and requires polar stereographic products.
  • Synthetic training data has a domain gap. Detector accuracy is reported on both synthetic and real imagery.

Technology stack

Chosen under three hard environment constraints — no Node.js/npm, Windows Application Control blocking newly-downloaded compiled DLLs (so no GDAL, rasterio, pandas or PyTorch), and read-only data on a mounted Drive.

Presentation   Three.js (ESM via CDN import-map) · vanilla ES modules · CSS · inline SVG
Service        FastAPI · Uvicorn · Pydantic v2
Analysis       NumPy · SciPy · scikit-image · OpenCV · scikit-learn · networkx
Data           numpy.memmap -> PDS3 .IMG · HTTP range -> PDS · WMTS -> NASA Moon Trek

No build step. No admin rights. 9 runtime dependencies, all verified importable on the target machine. See TECHNOLOGY.md for why each was chosen and what was rejected.

Attribution

All source data is public-domain NASA, USGS, PDS and ISRO material. Scientific practice nonetheless requires attribution, and the application displays the producer credit for every active layer. Academic output derived from this project must cite Robbins (2019) for the crater catalogue and the Space Robotics Group, Keio University for the Artificial Lunar Landscape dataset. Full obligations in DATASETS.md §9.
